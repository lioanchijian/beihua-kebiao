# 金智密码登录 · 短信二次验证协议（2026-10-26 实测）

> 对象：`sidportal.buct.edu.cn`（金智 linkid），service = `https://jwglxt.buct.edu.cn/sso/jziotlogin`
> 用途：密码正确但触发风控时，App 需要原地完成短信二次验证。
> 抓包脚本：`tools/probe/buct_login_probe.py`、`probe_2fa.py`、`probe_send_shape.py`、`probe_verify_shape.py`

## 一、核心变化：不再跳独立页面

旧版二次验证会 **302/渲染出一个独立的「二次身份验证」页面**，所以旧代码靠字符串判断：

```kotlin
html.contains("smsNoPhoneloginForm") || html.contains("二次身份验证")
```

2026-10 起认证页改为 Angular 单页，密码校验通过但需要二次验证时，服务端**照样返回 200 登录页**，
只在隐藏区塞入几个 `<p>`，由前端 JS 读取后切换成短信卡片：

```html
<p id="sso-second">true</p>
<p id="current-login-type">smsLogin</p>
<p id="second-auth-user-id">2024030677</p>
<p id="phone-number">18137551062</p>
<p id="login-page-flowkey">3eb09af9-…</p>   <!-- 已刷新，后续提交必须用新的 -->
```

关键点：短信卡片的表单 id 仍然叫 `smsNoPhoneloginForm`，但它由 JS 动态插入，
**服务端 HTML 里搜不到**。只靠旧的两个字符串必然漏判，最后落到「请检查账号密码或稍后重试」。

判定条件（新）：

```kotlin
sso-second == "true" && (current-login-type 为空 || current-login-type == "smsLogin")
```

## 二、完整调用链

| 步骤 | 请求 | 说明 |
|---|---|---|
| 1 | `POST /login?service=…`（type=UsernamePassword） | 返回 200 + `sso-second=true`，同时下发新 `login-page-flowkey` |
| 2 | `POST /sso-extend/protected/api/aggregate/sms/publicNoToken/generate`<br>body `{"phone":"<学号>","type":"DEFAULT"}` | 返回 `image/png` 图形码；学号与绑定手机号均可，服务端会解析 |
| 3 | `GET /sso-extend/protected/api/aggregate/sms/publicNoToken/sendCheckCaptcha/DEFAULT/<图形码>/<学号>/0008` | 业务号固定 `0008`；成功 `{"result":true}` |
| 4 | `POST /linkid/protected/api/aggregate/sms/verify`<br>body `{"phone":"<学号>","token":"<短信码>","delete":false}` | 业务码 200 才算通过 |
| 5 | `POST /login?service=…`<br>`type=smsLogin&password=<短信码>&username=<学号>&execution=<新 flowkey>` | 302 → `jwglxt/sso/jziotlogin?ticket=ST-…` |

错误码实测：

- 图形码错误：`{"code":412,"message":"2180000","data":{"errorCode":2180000}}`
- 短信码错误：`{"code":412,"message":"Precondition Failed","data":{"errorCode":9280078,"errorMessage":"请输入正确的验证码"}}`

所有 `/linkid/protected/…` 请求由前端拦截器改写到 `/sso-extend/…`，并附带
`Csrf-Key` / `Csrf-Value` / `Device-Id`：

```js
key = 32 位随机字母数字
enc = btoa(key)
half = enc.length / 2
Csrf-Value = MD5(enc.slice(0, half) + enc + enc.slice(half))
```

## 三、App 侧实现位置

| 位置 | 作用 |
|---|---|
| `BuctSsoLoginManager.isSecondarySmsPage()` | 判定二次验证（新增 `sso-second` 分支） |
| `BuctSsoLoginManager.extractSecondaryPhone()` | 从 `phone-number` 取全号并脱敏为 `181****1062` |
| `prepareSecondarySmsCaptcha()` / `sendSecondarySmsCode()` / `submitSecondarySmsCode()` | 第 2–4 步 |
| `submitSecondaryLoginForm()` | 第 5 步；被拒时回 `onSecondarySmsInvalid` 而不是重开弹窗 |
| `LoginScreen.SecondarySmsVerificationDialog()` | 弹窗 UI，沿用 SystemDialog / GlassTextField |
