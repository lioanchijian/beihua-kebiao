## 一、最重要的注意事项（红线，先看这条）



1. **不要主动上传 / 发布到服务器。** 只有你明确说「上传」时才上传；调试期间的安装包也不要顺手传到测试目录。本地改完不等于上线。

2. **正式通道固定两个文件，文件名不能改**：

* `version.json`

* `download/beihua-kebiao-latest.apk`

  另可保留 `download/beihua-kebiao-<版本>.apk` 作为**版本直链 / 历史归档**，也可作为 `downloadSources` 的第二个官网源；它不能替代 `latest.apk`。测试包一律放 `download/test/`，**绝不能覆盖** `beihua-kebiao-latest.apk`。

1. **上传顺序**：先传 APK → 再传 `version.json` → 最后验证。反过来会出现「清单已指向新版本、包还是旧的」，用户下到错包。

2. **所有下载源必须是同一个安装包**，SHA-256 必须一致。App 下载后会同时校验 **SHA-256 + 当前应用签名**，任一不符就取消安装并提示。

3. **只走 HTTPS**。不要加回明文 HTTP 备用源（`downloadUrlIp` 已删除）；HTTP 会被中间人替换清单，配合自动下载等于远程代码执行。

4. **不要换签名 / 不要换包名**。项目没有 `release-key.jks`，release 构建回退 debug 签名；换成正式 keystore 会让所有老用户必须卸载重装。

5. **桌面小组件的组件名不能改**。见「保留项」。

6. **外发 / 提交 GitHub 前必须脱敏**：`server/usage-stats/private/` 含真实统计 token，官网截图必须打码（姓名、学号、绩点、教师）。

7. **线上与本地可能不同步**：改完本地记得确认线上是否也要改；不要默认「本地改了 = 线上生效」。

8. **证书**：`dl.buctkb.cn` 的 Let's Encrypt 证书 2027-02-16 到期，OSS 上托管的是**副本**，续期后必须同步，详见第六节。

## 五、规范

### 4.1 版本号规范



* 格式固定 `1.0.9.N`（四段），`versionCode = 90 + N`。


  * 例：`1.0.9.15 → 105`，`1.0.9.16 → 106`。

* `scripts/release.sh`**&#x20;不适用本项目**：它要求干净工作区、只支持三段版本号，且会自动打 tag。发版一律**手动改** `app/version.properties` + 根 `CHANGELOG.md`。

* 版本号必须**全项目一致**：`version.properties`、`version.json`、`index.html`（至少 4 处）、`CHANGELOG.md`、`changelog.json`、`README.md`。

* 自检命令（在项目根跑）：



```
grep -rn "1\.0\.9\." --include="*.md" --include="*.json" --include="*.html" --include="*.properties" \
  website/ CHANGELOG.md README.md sources/android-app/app/version.properties | grep -v changelog.json
```

再人工确认 `changelog.json` 头部版本号。

### 4.2 哈希与下载源规范



* `version.json` 的 `sha256` 必须等于**正式包真实 SHA-256**：



```
sha256sum website/download/beihua-kebiao-latest.apk
```



* 所有下载源（官网 / 镜像 / GitHub 归档）**必须是同一个包**，哈希一致。不一致时 App 会静默取消安装并提示校验失败。

* `downloadSources` 每个 `url` 必须 `https://` 开头，App 会过滤掉非 HTTPS 源。

* `downloadSources` 字段 App 用 `JSONObject.optJSONArray` 解析，**老版本 App 会安全忽略**，可以放心加。

* App 端还有一份内置兜底源（`UpdateManager.DEFAULT_DOWNLOAD_SOURCES`），仅在清单没下发 `downloadSources` 时生效。**当前已清理为只保留官网**；线上清单现在下发官网、官网直链、OSS 三个源。以后换版本时，先上传新包到 OSS，再同时改清单里的 OSS URL；不要往兜底源写带版本号的旧链接。

### 4.3 上传 / 部署规范



* **不主动上传**；只有你明确说「上传」才执行。

* 正式通道 vs 测试目录严格分开。

* 上传顺序：APK → `version.json` → 页面 → 验证。

* 部署后必查：



```
curl -sS https://buctkb.cn/version.json | python3 -m json.tool
curl -sSI https://buctkb.cn/download/beihua-kebiao-latest.apk
```



* 服务器上的 `/root/dns_hook.py`、`/root/oss_put.py`、`/root/oss_cert_sync.py` 都**不含明文 AK**（走环境变量），不要往里写死密钥。

### 4.4 构建规范



* 用 `gradlew.bat`，且**不要手动设&#x20;**`JAVA_HOME`（自己算路径容易算错成 `C:\Program Files\Common Files\Oracle\Java`，导致 `JAVA_HOME is set to an invalid directory`）。

  `gradle.properties` 已指定 `org.gradle.java.home=C:\Users\li151\.jdks\jbr-21.0.11`。

* 正确命令（Git Bash）：



```
cd sources/android-app
unset JAVA_HOME
./gradlew.bat :app:assembleRelease --console=plain
# debug：./gradlew.bat :app:assembleDebug --console=plain
```



* 产物：`app/build/outputs/apk/{release,debug}/app-{release,debug}.apk`。

* release 构建回退 debug 签名（无正式 keystore），**不要**为了「正规」去新建 keystore。

* 装到手机测试：`adb devices` 确认在线 → `adb install -r <apk>`。ADB 路径 `/c/Users/li151/AppData/Local/Android/Sdk/platform-tools`。

### 4.5 GitHub 同步规范



* **真正的 git 仓库在&#x20;**`backup/git-snapshot`**（master）**，主工作区根目录**不是** git 仓库；改动要先拷进快照仓再提交 / 推送。

* 推送若遇 schannel / `CONNECT 502`，用验证过的组合：



```
git -c http.sslBackend=openssl -c http.version=HTTP/1.1 push origin master
```



* 提交前脱敏：`private/`、未打码截图、token 一律不进仓库。历史已用 `filter-branch` 清理过，别再引回。

* 每个正式版本在 GitHub 建 Release `v<版本>`，把 `<版本>.apk` 作为 Release asset 上传；官网「GitHub 下载」按钮指向 Release 页面，不再指向 `blob` / `raw` 文件页。

* 归档包 / Release asset 推上去后，用 API 或下载复核 `size` 与 SHA-256 和本地一致（曾出现 GitHub 上还是 14.5 MB 瘦身前旧包的情况）。

### 4.6 小组件规范



* 实例配置存 `widget_config` prefs：`title` / `account` / `source`；`source` 空 = 本机账号，`friend:<id>` = 朋友课表。

* 改完实例配置必须调 `ScheduleWidget.refreshAllWidgets(context)` 广播刷新。

* 设置 → 桌面小组件列表的标题 / 副标题必须在 `loadRows()` 刷新时解析成状态。

* 新旧 provider id 统一走 `WidgetProviders.weekIds()/dayIds()/refreshAll()`。

### 4.7 证书 / OSS 维护规范



* `dl.buctkb.cn` 是 Let's Encrypt **单域**证书（DNS-01，AliDNS 验证），到期 **2027-02-16**。

* 只签 `dl.buctkb.cn` 单域、**不动主站** `buctkb.cn`（主站走 nginx / HTTP-01 自动续期，不依赖 RAM 权限）。若换成泛域名 DNS-01，撤销权限后连主站证书都会续不上。

* OSS 上托管的是**证书副本**，续期后必须重新上传，否则 HTTPS 仍旧用过期旧证书。已配好 `renew_hook` → `/root/oss_cert_sync.py` 自动同步。

* 续期需要临时 RAM 授权（`AliyunDNSFullAccess` + `AliyunOSSFullAccess` + 证书服务），步骤见服务器 `/root/README-dl-cert.txt`；**用完即撤销**。

* 现在可以撤销全部权限，已生效的绑定 / 证书 / ACL / 下载都不受影响；只想全自动续期就得在服务器留长期 AK（有凭据风险，不推荐）。

* **当前镜像通道已恢复**：`1.0.9.16` 已上传 OSS，官网镜像按钮已恢复，清单里含「高速下载（OSS）」；以后换版本要同步更新 OSS 对象和清单 URL。

* 如果以后决定放弃 OSS 镜像：证书 / OSS 可以不再维护，但要同时删除官网镜像按钮、清单里的 OSS 源，并确认 App 兜底源不再指向旧包。
