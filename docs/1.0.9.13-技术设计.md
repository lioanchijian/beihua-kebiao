## 四、T3 更新 Cookie 支持二次验证（核心）

### 4.1 现状与根因
`utils/SessionRenewer.kt:26-38`：
```kotlin
gateway.login(school, user.username, user.accountPassword, object : PasswordLoginCallback {
    override fun onSuccess(cookie: String) = complete(LoginRecoveryOutcome.Cookie(cookie))
    override fun onCaptchaRequired(imageBytes: ByteArray) = complete(Failure(VerificationRequired))
    override fun onCaptchaInvalid() = complete(Failure(VerificationRequired))
    override fun onInvalidCredentials() = complete(Failure(CredentialsRejected))
    override fun onError(message: String) = complete(Failure(Network))
    // ← onSecondaryVerificationRequired / onSecondarySmsSent / onSecondarySmsInvalid 未实现
})
```
`PasswordLoginCallback` 默认实现把“需要二次验证”降级为 `onError(...)`，于是 UI 只看到“暂时无法连接”。

### 4.2 状态机
```
Idle ──request()──▶ LoggingIn ──onSecondaryVerificationRequired──▶ NeedCaptcha(phoneMasked, captcha)
                        │                                              │
                        │                                   sendSms(captcha) → SmsSent(expire)
                        │                                              │
                        └──onSuccess──▶ Done(cookie)         submitSms(code)
                                                                       │
                                                     onSecondarySmsInvalid → SmsInvalid(msg) → NeedCaptcha
                                                     onSuccess → Done(cookie)
```
- 网关实例在 `Verifying` 期间**保留**（不能 clearSensitiveState，否则状态丢失）。
- 超时（5 分钟无操作）→ 自动 `cancel()` 回 Idle。

### 4.3 API 变化
```kotlin
sealed interface SessionRecoveryResult {
    data class Recovered(val token: SessionToken) : SessionRecoveryResult
    data class NeedsLogin(val reason: RecoveryFailure, val message: String? = null) : SessionRecoveryResult
    object Superseded : SessionRecoveryResult

    // 新增
    data class NeedsSecondaryVerification(val phoneMasked: String, val captcha: ByteArray) : SessionRecoveryResult
    data class SecondarySmsSent(val expireSeconds: Int) : SessionRecoveryResult
    data class SecondarySmsInvalid(val message: String) : SessionRecoveryResult
}
```
```kotlin
object SessionRenewer {
    fun refreshCaptcha(onDone: (ByteArray?) -> Unit)
    fun sendSecondarySms(captcha: String, onDone: (SessionRecoveryResult) -> Unit)
    fun submitSecondarySms(code: String, onDone: (SessionRecoveryResult) -> Unit)
    fun cancelVerification()
}
```

### 4.4 UI：抽公共弹窗
`ui/system/SecondaryVerificationDialog.kt`（从 `LoginScreen.SecondarySmsVerificationDialog` 提取）：
```kotlin
@Composable
fun SecondaryVerificationDialog(
    phoneMasked: String,
    captcha: ByteArray?,
    smsCountdown: Int,
    smsError: String?,
    onRefreshCaptcha: () -> Unit,
    onSendSms: (captchaCode: String) -> Unit,
    onSubmit: (smsCode: String) -> Unit,
    onDismiss: () -> Unit
)
```
- 设置页与登录页共用，避免两套交互漂移。
- `SettingsRoute` 持有 `verificationState`，在 `SessionRenewer` 回到 `NeedsSecondaryVerification / SecondarySmsSent` 时渲染。

### 4.5 安全与清理
- 验证码、密码只存在内存；`onDismiss`、切换账号、`onCleared` → `cancelVerification()`；
- 不打印任何验证码/密码日志；
- 失败**不覆盖**现有 cookie（沿用 `saveCookieIfCurrent` 的 token 校验）。

### 4.6 回归清单
1. 正常密码登录（无风控）；
2. 密码登录触发二次验证 → 图形码 → 短信 → 成功；
3. 设置页「更新 Cookie」同样触发二次验证 → 成功；
4. 验证码输错 → 提示且能重发；
5. 取消 / 切账号 → 无残留状态；
6. 短信登录通道不受影响。

## 五、T5 匿名反馈会话

### 5.1 身份
| 字段 | 生成规则 |
|---|---|
| `install_id` | 已有随机 ID（`UsageStatsReporter`），抽 `analytics/InstallId.kt` |
| `display_id` | `BH-` + 6 位大写 Base32（去掉 0/O/1/I），冲突重试 |
| `nickname` | 词表随机（形容词 + 名词：晚风/薄荷/汽水/山楂/夜航/白露…），重名加两位数字 |
| `token` | 32 字节 `SecureRandom`，Base64URL；只存服务端与设备 |
| 管理员 | `install_id=admin:liuan`、`display_id=BH-ADMIN`、`nickname=柳岸` |

### 5.2 服务端表（`server/usage-stats/server.py` → `init()` 内追加）
```sql
CREATE TABLE IF NOT EXISTS fb_users(
  install_id TEXT PRIMARY KEY,
  display_id TEXT UNIQUE NOT NULL,
  nickname   TEXT NOT NULL,
  token      TEXT UNIQUE NOT NULL,
  created_at TEXT NOT NULL,
  last_seen  TEXT,
  banned     INTEGER DEFAULT 0
);
CREATE TABLE IF NOT EXISTS fb_messages(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  install_id TEXT NOT NULL,
  sender TEXT NOT NULL CHECK(sender IN ('user','admin')),
  body TEXT NOT NULL,
  created_at TEXT NOT NULL,
  read_by_user INTEGER DEFAULT 0,
  read_by_admin INTEGER DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_fb_thread ON fb_messages(install_id, id);
```

### 5.3 接口契约

### 5.4 App 端
**`network/FeedbackApi.kt`**
```kotlin
data class FeedbackIdentity(val displayId: String, val nickname: String, val token: String, val unread: Int)
data class FeedbackMessage(val id: Long, val sender: String, val body: String, val createdAt: String)

object FeedbackApi {
    suspend fun register(ctx: Context): FeedbackIdentity?      // 失败返回 null，界面给重试
```

- 超时 10s；失败静默重试一次。

**`ui/screen/FeedbackScreen.kt`**

```
 └ 说明卡（浅色）：你正在以匿名身份反馈，我们只能看到随机短号 BH-XXXXXX，看不到姓名/学号/密码。
```

## 九、版本与发布

1. 全部任务完成 → `assembleDebug` → 真机自测 → **debug 包只传 `download/test/`**；
2. 你确认 → 改 `app/version.properties`（1.0.9.13 / 103）+ 根 `CHANGELOG.md` → `assembleRelease`；
3. **发布**（更新 `version.json` + `latest.apk` + 官网）必须等你明确说“发布”；
4. 服务器改动（T5）部署前单独找你确认，并先备份 `stats.db`。
