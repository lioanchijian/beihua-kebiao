## 一、已证实的结论（浏览器侧，Chrome 普通窗口 + DevTools）

1. **register 200 只依赖 sidportal 域的有效 SESSION（HttpOnly cookie）**。
   - 同源 fetch `POST webauthn/register`（body=`username=2024xxxxxx&displayName=...&credentialNickname=TestX&requireResidentKey=false&sessionToken=null`）→ **200**，响应含 `publicKeyCredentialCreationOptions`（rp.id=sidportal.buct.edu.cn，7 种 alg，excludeCredentials 含已存在的"北化课表"凭据，sessionToken）。
   - **带不带 `X-CSRF-TOKEN` 头都是 200**（页面参数 `csrfToken` 全局未定义，实际不发）。
   - **删除 `tstfk` cookie 后仍 200**（`document.cookie='tstfk=;expires=...;path=/'` 再 fetch → 200）。→ CSRF 头、tstfk 均不是 400 根因。

2. **通行密钥管理是独立应用**：`https://sidportal.buct.edu.cn/account`（落地 `/?skipCustom=true`，Angular 挂根路径）。前端 register 源码（`window.register` / `getRegisterRequest` / `getWebAuthnUrls`）已从该页 Console 完整提取：
   - `getRegisterRequest(urls, username, displayName, credentialNickname, requireResidentKey=false)` → fetch `urls.register`（相对路径 `webauthn/register`），body=URLSearchParams{username, displayName, credentialNickname, requireResidentKey, sessionToken: session.sessionToken||null}（sessionToken 为空），headers 里 'X-CSRF-TOKEN':csrfToken（未定义→不发）。
   - `getWebAuthnUrls` = `{authenticate: "webauthn/authenticate", register: "webauthn/register"}`。

3. **loginnew bundle（登录/通行密钥前端）**：`/public/cas-login-new/main-es2015.f602431fc3ea63914618.js` + vendor + runtime + `830-es2015.1734f7d6c0314e2cc2e8.js`；页面配置 `caspagehash.js`、`deploy.js`。已全量下载到 `C:\lwh_tmp\loginnew_*.js`。

## 二、App 侧（BuctWebAuthnManager.kt）现状与差距

1. **App 注册流程**：密码登录 → `probeSafeCenterContext(sidCookie)`（GET sidself/cas-success → safe-center/index 建上下文，合并 cookie）→ `startRegistration(mergedCookie, ...)`（POST webauthn/register，`X-CSRF-TOKEN:"csrfToken"` 字面量 + Origin/Referer + Cookie 头）。
2. **差距**：App **从未真正加载过 `/?skipCustom=true` 通行密钥页本身**（页面 JS/内联 script 种的会话状态藏在 SESSION 里）。浏览器是"登录 → 访问通行密钥页 → 点创建 → register"。
   - **下一步（最高优先）**：在 App 的 probeSafeCenterContext 里**增加一次 GET `https://sidportal.buct.edu.cn/?skipCustom=true`**（带 sidportal SESSION），合并其 Set-Cookie 后再 register；或在浏览器验证"不访问该页直接 register 是否 400"。
3. **已在浏览器侧排除的假说**：CSRF 头、tstfk、页面访问前置（同源 fetch 不用先访问即可 200？——注意：当前浏览器会话**已经访问过**通行密钥页，页面态在 SESSION 服务端；需无痕新会话做对照实验）。
