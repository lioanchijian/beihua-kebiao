## 一、已确认根因

### 1. 注册会话上下文错误（已修复）
浏览器真实流程：普通密码登录 sidportal → GET https://sidportal.buct.edu.cn/account → POST /webauthn/register → 200。
原 App 走 admin-client OAuth / sidself/cas-success 链，得到的 sidportal 会话没有 register 权限，register 恒 400 operation not allowed。
已改为：
- loginSidPortalOnly 使用普通教务 service 登录；
- 302 后直接停在 sidportal，不再跟 ticket；
- probeSafeCenterContext 只 GET /account；
- MatchingMemoryCookieJar 不再把 SOURCEID_TGC/rg_objectid 误种到 sidself 域。

### 2. 系统通行密钥在该 RP 上走不通（已改用软件认证器）
- https://sidportal.buct.edu.cn/.well-known/assetlinks.json 返回 404。
- Google FIDO2 / Credential Manager 日志：RP ID cannot be validated、Failed to parse assetlinks.json。
- 默认 provider com.vivo.cipherchain 时会直接 CreateCredentialCancellationException / User cancelled the selector。
- Chrome 能创建是因为浏览器 web origin 通道；Android App 原生通道被 assetlinks 卡死。

### 3. 自研软件 WebAuthn 认证器已被服务器实测接受（关键）
电脑 Node 按 WebAuthn 标准生成 EC P-256 密钥、CBOR attestationObject(fmt=none)、assertion：
- POST /webauthn/register/finish → success=true
- 同密钥 POST /webauthn/authenticate/finish → success=true
证明学校服务端接受 App 自造认证器，不需要系统 passkey provider。
验证脚本（临时）：soft_authenticator_e2e.js、replay_app_attestation_mobile.js。

### 4. 两个 HTTP 细节坑（最后正在验证）
- JSONObject.toString() 会把 origin 转义成 https:\/\/... 写进 clientDataJSON，服务端会拒绝；已改为手工拼接 clientDataJSON。
- HttpUrl.toString() 带尾斜杠，曾导致请求头：
  Origin: https://sidportal.buct.edu.cn/
  Referer: https://sidportal.buct.edu.cn//account
  学校 WAF 会直接返回 500 Access Denied。
- 已修 BuctWebAuthnManager 的 Origin/Referer 为无尾斜杠、无双斜杠：
  Origin: https://sidportal.buct.edu.cn
  Referer: https://sidportal.buct.edu.cn/account（finish/register）
  Referer: https://sidportal.buct.edu.cn/login（authenticate）
- **最后这个修改后还没有重新跑完整 App 流程，明天第一件事验证 500 是否消失。**
