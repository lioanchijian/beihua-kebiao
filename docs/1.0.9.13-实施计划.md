## T3 更新 Cookie 支持二次验证（核心）

### 现状根因
`utils/SessionRenewer.kt` 的 `PasswordLoginCallback` 只实现了 `onSuccess / onCaptchaRequired / onCaptchaInvalid / onInvalidCredentials / onError`；
`onSecondaryVerificationRequired / onSecondarySmsSent / onSecondarySmsInvalid` 走接口默认实现 → `onError(...)` → 被归为 `RecoveryFailure.Network` → 「暂时无法连接」。

### 设计
1. `SessionRenewer` 保留网关实例，新增状态机：
   `Idle → LoggingIn → Verifying(phoneMasked, captchaBytes) → SmsSent(expire) → Done/Failed`
   - `refreshCaptcha()`：重新拉图形码
   - `sendSms(captcha)`：`gateway.sendSecondarySmsCode(captcha, cb)`
   - `submitSms(code)`：二次验证态下 `gateway.submitCaptcha(code, cb)`（内部走 smsLogin 重试）
   - `cancel()`：`gateway.clearSensitiveState()`，回 Idle
2. `SessionRecoveryResult` 增加：
   - `NeedsSecondaryVerification(phoneMasked, captchaBytes)`
   - `SmsSent(expireSeconds)`
   - `SmsInvalid(message)`
3. UI：把 `LoginScreen.SecondarySmsVerificationDialog` 抽成 `ui/system/SecondaryVerificationDialog.kt`（参数：手机号掩码、图形码、倒计时、四个回调），登录页与设置页共用，避免两套交互。
4. `SettingsRoute.refreshCookieManually()` 改为驱动该弹窗；成功后 toast「登录状态已更新」；失败按 `RecoveryFailure` 细分文案。
5. 安全：离开页面 / 切换账号 / 退出登录 → `cancel()`；验证码与密码只在内存，不落盘、不打日志。

### 验收
- 设置页点「更新 Cookie」触发风控 → 弹与登录页一致的验证窗 → 图形码 → 收短信 → 输码 → 成功；
- 取消后再次点击可重新发起；切换账号不会串会话；
- **回归**：普通密码登录、短信登录两条链仍正常。

## T5 匿名反馈会话（9.13 范围：只有「柳岸」一个会话）

### 身份与命名
| 字段 | 规则 |
|---|---|
| `install_id` | 复用 `UsageStatsReporter` 的随机 ID（抽成 `analytics/InstallId.kt`） |
| `display_id` | `BH-` + 6 位大写 base32，唯一，不可改 |
| `nickname` | 默认随机（词表：晚风/薄荷/汽水/山楂/夜航…，2–3 字 + 无数字重复问题用后缀去重），2–12 字可改 |
| `token` | 32 字节随机，注册时下发，之后所有请求带上；仅存服务端与设备 |

管理员固定：`install_id = admin:liuan`，`nickname = 柳岸`，`display_id = BH-ADMIN`。

### 服务端（`server/usage-stats/server.py`，复用 stats.db）
```sql
CREATE TABLE IF NOT EXISTS fb_users(
  install_id TEXT PRIMARY KEY,
  display_id TEXT UNIQUE NOT NULL,
  nickname TEXT NOT NULL,
  token TEXT UNIQUE NOT NULL,
  created_at TEXT NOT NULL,
  last_seen TEXT
);
CREATE TABLE IF NOT EXISTS fb_messages(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  install_id TEXT NOT NULL,
  sender TEXT NOT NULL,        -- user | admin
  body TEXT NOT NULL,
  created_at TEXT NOT NULL,
  read_by_user INTEGER DEFAULT 0,
  read_by_admin INTEGER DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_fb_thread ON fb_messages(install_id, id);
```

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/feedback/register` | `{installId, version, platform}` → 幂等建号，返回 `{displayId, nickname, token, unread}`；新号自动收到「柳岸」的欢迎语 |
| GET | `/api/feedback/thread?token=&since_id=` | 返回该用户全部消息（含管理员回复）+ `unread` |
| POST | `/api/feedback/send` | `{token, body}`，≤1000 字；不限条数 |
| POST | `/api/feedback/nickname` | `{token, nickname}`，2–12 字，敏感词粗筛 |
| GET | `/feedback?token=<admin>` | 后台：会话列表（匿名短号+昵称+末条+未读） |
| GET | `/feedback/thread?token=<admin>&install_id=` | 后台：单个会话全文（含版本号/最后活跃） |
| POST | `/feedback/reply` | `{token, install_id, body}` → `sender='admin'` |

- 所有响应 JSON；后台页 HTML 全量转义；
- 频率：`register` 每 IP 10 次/分；`send` 每人 60 条/分（只对管理员，放宽）；
- 日志不记录正文与 token。

### App 端
1. `analytics/InstallId.kt`：抽自 `UsageStatsReporter`，首次生成并持久化。
2. `network/FeedbackApi.kt`：register/thread/send/nickname（OkHttp，10s 超时）。
3. `ui/screen/FeedbackScreen.kt`（独立页面，非弹窗）：
   - 顶部说明条：「你正在以匿名身份反馈。我们只能看到随机短号 `BH-7F3K2Q`，看不到你的姓名、学号或密码。」
   - 头像色块 + 昵称（点击可改）+ 短号；
   - 气泡列表：我（右侧灰蓝）、柳岸（左侧浅紫）；时间分隔；
   - 底部输入框 + 发送；失败保留草稿可重试；
   - 进入即拉取，打开期间每 5 秒轮询；离开停止。
4. 设置入口：`SettingsScreen` 增加「意见反馈」行（图标 + 副标题「匿名，直接和柳岸说」），右侧未读红点；未读数在进入设置/启动时拉一次。

### 后台页面（两栏，像 QQ）
- 左栏：`短号 · 昵称`、末条消息摘要、时间、未读红点；按最后消息倒序；
- 右栏：气泡对话 + 输入框（回车发送）；
- 顶部：短号、昵称、版本号、最后活跃时间（关联 installs 表），无实名信息；
- 「标记已读」按钮。

### 验收
- 新装/未登录能发消息；后台能看到并按短号折叠；
- 后台回复 → App 重新打开能看到 + 设置页红点；
- 改名后后台列表同步显示新昵称。

## T4 快速切换账号 + 小组件按实例选账号

### App 内切换
1. `ScheduleScreen` 顶栏加「账号芯片」（头像色块 + 昵称，宽屏显示短号尾号）。
2. 点击 → `AccountSwitcherSheet`（ModalBottomSheet）：
   - 已保存账号列表（昵称、学号后四位、当前标记）；
   - 点选 → `UserManager.switchToAccount(key)`；
   - 底部「管理账号」→ 设置页账号管理；
   - 切换时 `requests.cancelAll()` + 清页面态 + 重新加载课表/成绩/考试。
3. 切换中显示轻量 loading，失败回滚并提示。

### 小组件按实例选账号
- `WidgetConfigStore.accountKey(id)`：空 = 跟随当前账号；
- `ScheduleDayWidgetService` / `ScheduleWidgetService` 取 accountKey 时优先实例配置；
- 该账号无缓存 → 卡片显示「该账号暂无课表缓存，打开 App 同步一次」；
- 配置页（T1）里就是账号下拉。

### 验收
- 课表页切到账号 B → 课表/成绩变 B 的；
- 两个小组件分别选 A / B → 各自显示正确；
- 未配置的小组件仍跟随当前账号（老用户无感）。

|---|---|
| T3 改登录链路可能影响正常登录 | 续期失败绝不覆盖现有 cookie；每次改动跑「密码登录 / 短信登录 / 续期」三条回归 |
