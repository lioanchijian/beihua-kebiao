# 签名迁移与更新通道（1.0.9.19 / 1.0.9.20）

> 记录时间：2026-11-23
> 目的：把正式包从 `CN=Android Debug` 迁到新的 release 证书，同时保证老用户能覆盖安装、账号/课表/桌面小组件不丢。

## 1. 两把证书

| 角色 | DN | SHA-256 | 密钥 | 有效期 |
|---|---|---|---|---|
| 旧 debug（桥接期） | `C=US, O=Android, CN=Android Debug` | `f913790f6805b6ec92fc431568af048f2210bd24530e1f0e1b982bd5f694c235` | RSA 2048 | 2026-09-19 ~ 2056-09-11 |
| 新 release（1.0.9.20 起） | `CN=BUCTKB Release, OU=BUCTKB, O=BUCTKB, L=Beijing, ST=Beijing, C=CN` | `8c04dd4a0460730f9c278799ecfb56c208a526bf0fa960e198d405b1d05e761f` | RSA 4096 | 2026-11-23 ~ 2054-04-10 |

- 私钥、口令、lineage 在 `secrets/signing/`，不在源码目录，不提交 Git。
- 详细备份位置和恢复方法见 `secrets/signing/README.md`。

## 2. 两个更新清单

| 客户端版本 | 请求路径 | 服务器文件 | 指向 |
|---|---|---|---|
| `<= 1.0.9.18` | `https://buctkb.cn/version.json` | `website/version.json` | 固定 1.0.9.19 桥接包 |
| `>= 1.0.9.19` | `https://buctkb.cn/version-latest.json` | `website/version-latest.json` | 1.0.9.20 正式签名包 |

`UpdateManager.kt` 的顺序是：先 `version-latest.json`，失败再回退 `version.json`。所以：

- 1.0.9.18 只会看到 1.0.9.19，并在更新弹窗看到桥接说明；
- 装上 1.0.9.19 后，才会请求 `version-latest.json` 并看到 1.0.9.20；
- 1.0.9.20 再检查时，两个清单都不会给出更高版本。

**不要**把 `version.json` 改成 1.0.9.20。老客户端的更新器只读这个路径，改了会让老用户直接面对新签名包而拒绝自动更新。

## 4. 服务器部署顺序

站点根：`/var/www/beihua`；下载目录：`/var/www/beihua/download`。

### 第一阶段：只发桥接版

1. 上传 `beihua-kebiao-1.0.9.19.apk` 到 `download/`。
2. 上传本地 `website/version.json` 到 `/var/www/beihua/version.json`。
3. 验证：
   ```bash
   curl -sS https://buctkb.cn/version.json | python3 -m json.tool
   curl -sSI https://buctkb.cn/download/beihua-kebiao-1.0.9.19.apk
   ```
4. 此时老用户检查更新只会收到 1.0.9.19，弹窗里会显示桥接说明。

### 第二阶段：桥接版铺开后发正式签名版

1. 上传 `beihua-kebiao-1.0.9.20.apk` 到 `download/`。
2. 用同一份文件覆盖 `download/beihua-kebiao-latest.apk`。
3. 上传本地 `website/version-latest.json` 到 `/var/www/beihua/version-latest.json`。
4. 不要动 `/var/www/beihua/version.json`，它必须继续留在 1.0.9.19 桥接版。
5. 验证：
   ```bash
   curl -sS https://buctkb.cn/version.json | python3 -m json.tool
   curl -sS https://buctkb.cn/version-latest.json | python3 -m json.tool
   curl -sSI https://buctkb.cn/download/beihua-kebiao-latest.apk
   curl -sSI https://buctkb.cn/download/beihua-kebiao-1.0.9.20.apk
   ```
6. 检查两个清单的 `sha256` 与实际文件一致；`version.json` 的 `versionCode` 必须还是 109。

### 可选 Nginx：禁止清单被缓存

如果站点对 JSON 配了长缓存，给两个清单加：

```nginx
# 用 expires -1 而不是 add_header Cache-Control，避免覆盖站点级 HSTS。
location = /version.json {
    default_type application/json;
    expires -1;
    try_files $uri =404;
}
location = /version-latest.json {
    default_type application/json;
    expires -1;
    try_files $uri =404;
}
location = /download/beihua-kebiao-latest.apk {
    expires -1;
    try_files $uri =404;
}
```

完整片段见 `server/update/nginx-version-cache.conf`。App 请求本身带 `Cache-Control: no-cache`，通常不需要改 Nginx；只有出现过“清单更新了但 App 还读旧版”才加。
